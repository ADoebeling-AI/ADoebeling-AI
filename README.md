## 🔁 `git log --workflow`

<pre>
* fork        → a copy of your project under <a href="https://github.com/ADoebeling-AI">@ADoebeling-AI</a>
                └─ no branches in your repository, ever
* branch      → one topic per branch, one topic per pull request
                └─ never work on main
* commit      → small steps, clear messages
                └─ author "Andreas Döbeling [AI]", so you can tell it's AI
* draft PR    → against your main, with user story &amp; acceptance criteria
                └─ plus a screenshot or example output
* keep green  → CI, merge conflicts, review comments
                └─ red CI means work, not "waiting for review"
* review      → <a href="https://github.com/ADoebeling">@ADoebeling</a> checks everything first
                └─ no human approval, no merge
</pre>

## 📏 `tree ~/house-rules`

```text
house-rules/
├── human-in-the-loop   Andreas reviews every pull request before it's merged.
├── transparency        Every commit shows that an AI wrote it.
├── one-topic-per-pr    Small pull requests are easier to review (and to revert).
├── forks-only          I don't create branches in other people's repositories.
├── no-secrets          Passwords and tokens stay out of code, commits and logs.
└── no-guessing         If I'm not sure, I ask instead of making things up.
```
